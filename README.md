# Flip Analytics Skills

Плагин-маркетплейс со скиллами для работы с Flip Analytics — аналитикой видимости бренда в ответах нейросетей.

## Установка

В Claude Code:

```
/plugin marketplace add Adrinalin4ik/flip-analytics-skills
/plugin install flip-analytics@flip-analytics-skills
```

После установки скиллы подхватываются автоматически: модель вызывает нужный по описанию, либо его можно позвать явно — например `/flip-generate-report`.

Для локальной разработки вместо первой команды:

```
/plugin marketplace add ./path/to/flip-analytics-skills
```

## Что внутри

```
.claude-plugin/marketplace.json          — каталог плагинов этого репозитория
plugins/flip-analytics/
  .claude-plugin/plugin.json             — манифест плагина
  skills/
    flip-generate-report/
      SKILL.md                           — процедура: организация, сбор, сохранение, правка
      references/data.md                 — структура данных отчета
      references/methodology.md          — методология выводов
      references/blocks.md               — карточки блоков 1.1–3.3
      references/checklist.md            — чек-лист перед сохранением
```

### Скиллы

| Скилл | Назначение |
| --- | --- |
| `flip-generate-report` | Сборка аналитического отчета: чтение данных через `get_report_data`, авторские выводы по блокам, сохранение через `create_report`, правка через `get_report_document` + `update_report`. Плюс методология выводов и чек-лист проверок. |

## Как добавить новый скилл

1. Создать папку `plugins/flip-analytics/skills/<имя-скилла>/` и в ней `SKILL.md`.
2. В начале `SKILL.md` — фронтматтер:

   ```markdown
   ---
   name: имя-скилла
   description: Что делает и КОГДА его применять — по этому тексту модель решает, брать скилл или нет.
   ---
   ```

3. Тело файла — инструкции для модели. Ориентир — до ~5 тысяч токенов: `SKILL.md` грузится в контекст целиком, как только скилл сработал. Все объемное (справочники по данным, таблицы, методология, чек-листы) выносить в `references/` и ссылаться оттуда с указанием, КОГДА это читать — такие файлы попадают в контекст только когда действительно понадобились.
4. Добавить строку в таблицу скиллов выше и поднять версию (см. ниже).

## Версионирование

`version` живет в двух файлах и всегда меняется в обоих: `plugins/<плагин>/.claude-plugin/plugin.json` и `.claude-plugin/marketplace.json` (там же общая версия каталога).

- **Патч** (0.2.0 → 0.2.1) — уточнение формулировок, примеры, опечатки: поведение скилла то же.
- **Минор** (0.2.1 → 0.3.0) — новый скилл, новый шаг в процедуре, изменение того, что скилл делает или о чем спрашивает пользователя.
- **Мажор** (0.x → 1.0.0) — несовместимая переделка: скилл переименован или разделен, поменялся сам порядок работы.

Версию поднимаем в том же коммите, что и правку, а не отдельным «bump»-коммитом задним числом.

Отдельный плагин (а не новый скилл внутри `flip-analytics`) имеет смысл заводить, когда появится набор скиллов для другой области: создать `plugins/<имя>/` с собственным `.claude-plugin/plugin.json` и дописать его в `plugins` в `.claude-plugin/marketplace.json`.
